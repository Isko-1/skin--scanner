# skin-scanner (P0)

## Setup
1. Создать проект Supabase, выполнить `supabase/schema.sql` в SQL editor.
2. Создать Next.js app (App Router) и скопировать сюда `app/`, `lib/`.
3. Установить зависимости: `@supabase/supabase-js`. Tailwind должен быть настроен (страницы используют utility-классы).
4. Заполнить `.env.local` по образцу `.env.example`.
5. Модель: найти готовые веса под HAM10000/ISIC на Hugging Face (image-classification task), указать `HF_MODEL_ID` и `HF_TOKEN` — см. комментарий в `lib/classifier.ts`.

## Что уже готово (P0)
- `supabase/schema.sql` — moles, photo_analyses, spectral_readings, RLS, storage bucket, realtime.
- `/capture` — камера, оверлей-гид, отсечение смазанных кадров (Laplacian variance) и явно-не-кожи кадров до загрузки.
- `/api/classify` — принимает `{mole_id, image_path, sharpness_score}`, гоняет через модель, пишет `photo_analyses`.
- `/api/spectral` — принимает данные от спектрального щупа (см. "Спектральный щуп" ниже).
- `/mole/[id]` — история сканов родинки + live-результат щупа.
- `/dashboard` — случаи с risk_score выше порога, по убыванию.

## Спектральный щуп (ESP32 + AS7341) — закрыто
Физическое дополнение: ручка-щуп на ESP32 с лазерной линией 650нм и спектральным сенсором AS7341, подключается к сайту напрямую по WiFi (не Bluetooth — Web Bluetooth не работает ни в одном браузере на iOS, это ограничение платформы Apple, а не баг; ESP32 обходит его тем, что вообще не использует телефон как посредника).

- `firmware/pen-probe/pen-probe.ino` — прошивка: по нажатию кнопки включает лазер, читает 10 каналов AS7341, шлёт HTTPS POST на `/api/spectral` с секретом в заголовке `Authorization`.
- `app/api/spectral/route.ts` — принимает данные (авторизация — статический `SPECTRAL_DEVICE_SECRET` из `.env.local`, у устройства нет логина), считает индексы, пишет `spectral_readings`.
- `lib/spectral.ts` — индекс эритемы/меланина по каналам AS7341 — **эвристика по направлению из литературы по diffuse-reflectance spectroscopy, не обученная и не клинически валидированная модель**. См. HONESTY NOTE в файле.
- `lib/spectral-patterns.ts` — сравнение формы спектра с эталонными профилями (косинусное сходство). Эталоны в `PATTERN_LIBRARY` **придуманы вручную по направлению из той же литературы, реальных референсных сканов пока нет** — заменить на усреднённые реальные показания, как только они появятся (см. комментарии в файле).
- `components/spectral-live.tsx` — Supabase Realtime: результат появляется на `/mole/[id]` сам, без перезагрузки, как только щуп прислал данные.

**Известное ограничение MVP:** у щупа нет экрана/клавиатуры, поэтому `mole_id` зашит в прошивку константой (`PEN_MOLE_ID` в `pen-probe.ino`) — чтобы сканировать другую родинку, нужно скопировать её uuid из URL страницы родинки и перепрошить. Годится для одного человека, тестирующего один щуп; для реальных пользователей нужен pairing-флоу без перепрошивки (см. комментарий "KNOWN MVP LIMITATION" в начале прошивки).

**Важно по содержанию:** результат щупа на сайте нигде не называется "вероятностью рака" — только "похоже на такой-то паттерн" с честной пометкой, что это не диагноз. Формулировка "процент вероятности рака" сознательно не используется: ни один найденный источник (включая коммерческий SIAscope на похожем диапазоне волн 400-1000нм) не показал точности, достаточной, чтобы давать такую цифру пользователю без риска ввести в заблуждение.

## Авторизация и приватность данных (закрыто)
Ранее `/`, `/mole/[id]` и `/dashboard` ходили в базу через `supabaseAdmin` (service-role ключ) без проверки владельца — главная страница показывала родинки всех пользователей всем подряд, а `/mole/[id]` открывался по любому UUID независимо от того, чей он (IDOR). `ensureSession()` создавал только анонимные сессии, реальной регистрации не было.

Добавлено:
- `/login`, `/register`, `/logout` — email/password через Supabase Auth (`@supabase/ssr`), плюс вход через Google (`/auth/callback` обменивает OAuth-код на сессию).
- `middleware.ts` — обновляет сессионную cookie на каждом запросе, редиректит неавторизованных на `/login`, и отдельно гейтит `/dashboard` по `app_metadata.doctor === true`.
- `lib/supabase/server.ts` и `lib/supabase/client.ts` — сессионные клиенты вместо `supabaseAdmin` на страницах; RLS-политики `own moles` / `own photo_analyses` из `supabase/schema.sql` сами фильтруют данные по `auth.uid()`.
- `/api/classify` — проверяет, что `mole_id` в запросе принадлежит авторизованному пользователю (раньше это можно было обойти, зная чужой `mole_id`).
- Главная страница (`/`) — карточки личной статистики: кол-во родинок, всего сканов, средний/макс. risk score.

`supabaseAdmin` (`lib/supabase.ts`) используется только внутри `/api/classify` и `/api/spectral` (доверенный серверный код с собственной проверкой владельца/секрета) — доктор-дашборд переведён на сессионный клиент и уже готовые RLS-политики `doctors see all ...`.

## Мобильная вёрстка `/capture` (закрыто)
В `app/layout.tsx` отсутствовал `<meta name="viewport">` — мобильные браузеры рендерили страницу в масштабе ~980px и зумили её, из-за чего кнопка съёмки уменьшалась и требовала скролла/зума, чтобы попасть по ней. Добавлен `viewport` export в `app/layout.tsx`. На `/capture` `min-h-screen` заменён на `h-dvh overflow-hidden`, чтобы плавающая адресная строка мобильного браузера не могла увести нижнюю панель с кнопкой за пределы экрана.
